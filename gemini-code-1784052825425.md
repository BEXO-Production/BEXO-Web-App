# Nex AI: Feature Expansion & Architecture Plan

## 1. Domain Routing & Post-Purchase Dashboard

### Routing Logic
*   **Wildcard DNS:** Configure `*.mybexo.com` at the DNS provider level (e.g., Cloudflare) to point to the Next.js application.
*   **Middleware Rewrites:** Implement Next.js middleware to intercept requests to `kavin.mybexo.com` and rewrite them to the dynamic user route `mybexo.com/[user_slug]`.

### Dashboard UI/UX Improvements ("Command Center")
*   **Aesthetic Overhaul:** Transition the current clean, light-mode dashboard (as seen in `Screenshot 2026-07-14 at 11.38.48 PM.jpg` and `Screenshot 2026-07-14 at 11.38.55 PM.jpg`) into a dark-mode cyberpunk design.
*   **Layout:** Utilize a Bento Grid layout for the main statistics. 
*   **Visual Elements:** Apply glassmorphism (translucent backgrounds with background blur) to the bento cards, highlighted by subtle neon accent borders (e.g., neon blue or purple) to indicate active states.
*   **State Rendering:** Once a user completes a purchase, intercept any subsequent navigation to the onboarding or pricing page (`Screenshot 2026-07-14 at 11.37.23 PM.jpg`) and redirect them to this Command Center. Display the active plan prominently with an animated "Upgrade" option.

## 2. The Floating Action Button (FAB) & Update Workflows

### FAB Placement & Animation
*   **Placement:** Fixed to the bottom-right of the viewport across the dashboard.
*   **UX/Animation:** Use Framer Motion for micro-interactions. On click, the `+` icon should rotate 45 degrees (becoming an 'x' to close) while smoothly fanning out two distinct, glowing options: **'Price My Resume'** and **'Post an Update'**.

### Flow A: Price My Resume
1.  **Gatekeeping:** Query the user's `price_resume_count` against their `plan_type` limit. Free users attempting this action will trigger a glassmorphic upgrade modal.
2.  **Upload Interface:** Launch the PDF upload interface (`Screenshot 2026-07-14 at 11.38.03 PM.jpg`). Ensure the drag-and-drop zone provides visual feedback (neon outline change) on file hover.
3.  **Storage:** Buffer the PDF and push it to Cloudflare R2 object storage.
4.  **Processing & DB Transaction:** As the server processes the newly parsed resume data, execute a strict SQL transaction in PostgreSQL:
    *   `DELETE` existing parsed portfolio entries for the user.
    *   `INSERT` the new payload.
    *   *Why:* This prevents orphaned rows or duplicated data during the sync process.

### Flow B: Post an Update
1.  **Gatekeeping:** Verify the user's `update_count` against their active period limit.
2.  **Selection Modal:** Present a modal allowing the user to select the update category. This maps to the existing lists: Education (`Screenshot 2026-07-14 at 11.38.18 PM.jpg`), Experience (`Screenshot 2026-07-14 at 11.38.11 PM.jpg`), Projects (`Screenshot 2026-07-14 at 11.38.24 PM.jpg`), Certificates (`Screenshot 2026-07-14 at 11.38.30 PM.jpg`), Achievements (`Screenshot 2026-07-14 at 11.38.36 PM.jpg`), and Research (`Screenshot 2026-07-14 at 11.38.40 PM.jpg`).
3.  **Submission & Auto-Save:** The user inputs details (and uploads images to R2 if applicable). On form blur or submit, the data is automatically pushed to the database.
4.  **Optimistic UI:** The frontend immediately reflects the new entry with its associated image, providing instant gratification.

## 3. Tiered Feature Logic & Database Schema

### Logic Matrix
| Feature | Free Plan | Lifetime Plan | Yearly Subscriber | 
| :--- | :--- | :--- | :--- | 
| **Recomplete Resume** | 1 per month (resets every 50 days) | 3 per 30 days | 10 per month (resets every 30 days) |
| **Post Update** | 1 per month (resets every 30 days) | 3 in 30 days | 10 per month (resets calendar month) | 
| **Price My Resume** | 0 (Not allowed) | 1 per month (resets calendar month)| 2 per month (resets calendar month) | 

### PostgreSQL Architecture
Create a new table `user_usage_cycles` to track these highly specific reset intervals:

```sql
CREATE TABLE user_usage_cycles (
  user_id UUID REFERENCES users(id),
  plan_type VARCHAR(50) NOT NULL,
  
  recomplete_count INT DEFAULT 0,
  recomplete_reset_date TIMESTAMP WITH TIME ZONE,
  
  update_count INT DEFAULT 0,
  update_reset_date TIMESTAMP WITH TIME ZONE,
  
  price_resume_count INT DEFAULT 0,
  price_resume_reset_date TIMESTAMP WITH TIME ZONE,
  
  PRIMARY KEY (user_id)
);
